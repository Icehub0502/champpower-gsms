## กติกาที่ห้ามละเมิด

### 1. รถมาถึง = เลื่อนสถานะ ไม่ใช่สร้างใหม่

นี่คือบั๊กที่ทำร้ายต้นแบบที่สุด อ่าน `CLAUDE.md` §5.8 และ `docs/DESIGN_DEPOSIT_QUEUE_LINE.md` ให้จบก่อน

- ฐานข้อมูลกันไว้แล้วด้วย `uq_jobs_booking` + trigger — **อย่าพยายามเช็คซ้ำในโค้ด** ให้มันพังที่ฐานข้อมูลแล้วแปลง error เป็นข้อความที่คนอ่านรู้เรื่อง
- **ห้ามมีปุ่มที่ชื่อว่า "สร้างคิวใหม่" บนหน้าจอที่มี booking อยู่แล้ว** ปุ่มต้องชื่อ "รถมาถึงแล้ว"
- หน้าคิวอ่าน `queue_today` **ที่เดียว** ห้าม fetch สองที่แล้ว merge ใน React

### 2. รูปเป็นไฟล์ ไม่ใช่ base64

ต้นแบบเก็บ `job_photos.photo_data LONGTEXT` ซึ่งทำให้ตารางบวมจนช้า — **ห้ามทำซ้ำ**

- ไฟล์ลง `storage/<shop_id>/<yyyy-mm>/<uuid>.<ext>` · แถวใน `files` เก็บ path ไม่ใช่เนื้อไฟล์
- **ห้ามเสิร์ฟด้วย `express.static`** (`CLAUDE.md` §12) ต้องผ่าน route ที่ตรวจ JWT และตรวจว่า
  `files.shop_id` ตรงกับ `active_shop_id` ในโทเคน
- ย่อรูปฝั่ง client ก่อนอัปโหลด (ต้นแบบมี `utils/resizeImage.js` ยกมาได้) แล้วทำ thumbnail ฝั่ง server
- จำกัดขนาดและชนิดไฟล์ ปฏิเสธอย่างอื่น

### 3. ทุก query ผ่าน `withShop()`

ห้ามเรียก `unscoped()` กับข้อมูลร้าน — type จับให้แล้ว ถ้าต้อง cast เพื่อให้ผ่าน แปลว่าทำผิดทาง

### 4. หน้าจอใช้โทเคนเดิม

`CLAUDE.md` §16 — ใช้ `AppShell` `Icon` `Modal` `PlateBadge` `StatusTrack` `JobCard` ที่มีอยู่
ต้องการสีใหม่ → เพิ่มโทเคนใน `:root` ห้ามเขียนค่าดิบ · **ทดสอบที่ 390px**

### 5. ทะเบียนรถ

`vehicles.plate_key` เป็น generated column อยู่แล้ว — ใช้มันค้นหา ไม่ใช่ `LIKE` บน `plate` ดิบ
ค้นด้วยทะเบียนต้องเจอแม้พิมพ์เว้นวรรคต่างกัน
