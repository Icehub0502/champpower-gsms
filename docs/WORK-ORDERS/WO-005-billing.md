## 1. ตัดออก — ตัดสินจากข้อมูลจริง

**ลายเซ็นบนจอ (`customer_signature` / `staff_signature`) — ตัดทิ้ง**

ข้อมูลจาก production:
- ใบเสร็จ 358 ใบ → มีลายเซ็นลูกค้า **46**
- ใบเสนอราคา 482 ใบ → มีลายเซ็นลูกค้า **1** / ลายเซ็นพนักงาน **0**

ฟีเจอร์นี้แทบไม่มีใครใช้ ลูกค้าเซ็นบนกระดาษที่พิมพ์ออกมาแทน — ซึ่งเก็บไว้ได้จริงกว่า
ตัดออกประหยัดเวลาไปทำมัดจำ

ตัดด้วย: ห้อง VAT · ใบกำกับภาษี · e-Tax · ใบลดหนี้ · ใบกำกับอย่างย่อ · บอท LINE ปิดบิล

## 2. ค่าที่ดึงจากข้อมูลจริง ไม่ต้องถามใคร

### รูปแบบเลขที่เอกสาร (ตั้งใน `document_series`)
| เอกสาร | ของเดิมล่าสุด | รูปแบบ |
|---|---|---|
| ใบเสร็จ | `RC690916002` | `RC{BE}{MM}{DD}{SEQ:3}` — **พ.ศ. 2 หลัก** รันใหม่ทุกวัน |
| ใบงาน | `JB-260916-006` | `JB-{YY}{MM}{DD}-{SEQ:3}` — **ค.ศ. 2 หลัก** รันใหม่ทุกวัน |
| ใบเสนอราคา | `IV...` | `IV{YY}{MM}{DD}{SEQ:3}` — ค.ศ. รันใหม่ทุกวัน |

> ใบเสร็จใช้ พ.ศ. แต่ใบงานใช้ ค.ศ. — ไม่สม่ำเสมอ แต่นี่คือของจริงที่พนักงานคุ้นอยู่ **ห้ามไป "แก้ให้ตรงกัน" เอง**
> เพราะรันใหม่ทุกวัน จึงไม่ชนกับเลขเก่า ตราบใดที่ระบบเก่าหยุดออกเลขในวันที่เปลี่ยน

### วิธีชำระเงิน — 4 แบบเท่านั้น
`โอน` (229) · `เงินสด` (45) · `บัตรเครดิต` (43) · `QRCode` (37)
ค่าเริ่มต้น = `โอน`

### เหตุผลที่ปฏิเสธ — **เก็บไว้ ใช้จริง**
ใบเสนอราคาถูกปฏิเสธ **30%** (147 จาก 482) เจ้าของร้านต้องการรายงานนี้
บรรทัดที่ถูกปฏิเสธต้อง**ยังแสดงบนเอกสาร** เป็นหลักฐานว่าเคยเสนอแล้วลูกค้าไม่เอา

## 3. มัดจำ — งานยากที่สุด ตัดสินแล้ว

### หลักการที่ห้ามผิด
> **มัดจำคือเงินที่รับไว้ผูกกับ "ลูกค้า" ไม่ใช่ฟิลด์ในใบเสนอราคา**
> ระบบเก่าเก็บเป็น `deposit_amount` บนทั้ง `quotations` และ `receipts` — นั่นคือต้นเหตุของปัญหาที่ Ice เจอ
> เงินก้อนเดียวถูกบันทึกสองที่ แล้วไม่มีใครรู้ว่าอันไหนจริง

### ตาราง `deposits`
`customer_id` · `amount` · `received_at` · `method` · `note` · `status`

`status`: `held` → `applied` | `refunded` | `forfeited` | `credited`

### กติกา
1. **ห้ามหักมัดจำอัตโนมัติ** พนักงานต้องเลือกก้อนที่จะใช้ตอนปิดบิลเสมอ
2. เงินก้อนเดียวแบ่งใช้หลายงานได้ แต่ยอดคงเหลือต้องไม่ติดลบ
3. ทุกการเปลี่ยน status ต้องบันทึก **ใคร / เมื่อไหร่ / เหตุผล** เหตุผลเป็นข้อความบังคับกรอก
4. **ลูกค้าไม่กลับมา / ยกเลิกงาน → ระบบไม่ตัดสินเอง** เปิดให้เลือกทั้ง 3 ทาง (คืน / ริบ / เก็บเป็นเครดิต)
   พร้อมช่องกรอกเหตุผล — *(ตามที่ Ice สั่ง: "แล้วแต่กรณี ให้คนตัดสิน")*
5. **หน้าจอ "มัดจำค้าง"** แสดงทุกก้อนที่ยัง `held` เรียงตามอายุ ก้อนที่ค้างนานต้องเด้งขึ้นบนสุด
   — ของแบบนี้ถ้าไม่มีหน้าจอบังคับให้เห็น จะถูกลืมจนกลายเป็นเงินที่ไม่มีใครรู้ว่าของใคร

## 4. ใบเสร็จ — รับเงินครบเท่านั้น

*(ตามที่ Ice ยืนยัน: ไม่เคยมีลูกค้าค้างชำระ)*

- ยอดที่รับ **ต้องเท่ากับ** ยอดสุทธิพอดี ไม่เท่า = ออกใบเสร็จไม่ได้ พร้อมข้อความบอกว่าขาด/เกินเท่าไหร่
- **ไม่มีระบบลูกหนี้ ไม่มีชำระบางส่วน ไม่มีค้างชำระ** — ห้ามใครแอบใส่ "เผื่อไว้"
- ใบเสร็จคิดเฉพาะบรรทัดที่**ทำจริง** พนักงานติ๊กทีละบรรทัดก่อนออกใบเสร็จ
  บรรทัดที่อนุมัติแล้วแต่ไม่ได้ทำ → ปล่อยของที่จองไว้คืนสต๊อก (เมื่อโมดูลสต๊อกพร้อม)
- เอกสาร**แก้ไม่ได้เมื่อได้เลขที่แล้ว** แก้ = ออกใบใหม่

### รายงานสองตัวที่ห้ามรวมกันเด็ดขาด
| รายงาน | นับจาก |
|---|---|
| **เงินเข้าวันนี้** | วันที่ในใบเสร็จ + วันที่รับมัดจำ |
| **ยอดขายวันนี้** | วันที่ปิดงาน |

มัดจำที่รับวันที่ 1 แล้วปิดงานวันที่ 10 จะอยู่คนละรายงาน **ถ้ารวมกันเมื่อไหร่ ตัวเลขจะผิดทั้งคู่**

## 5. ใบเสนอราคา + ราคา

*(ตามที่ Ice สั่ง: ดึงอัตโนมัติ แก้ทับได้ + เพิ่มรุ่นใหม่ได้ทันที)*

1. เลือกยี่ห้อ/รุ่น → ราคาขึ้นเองจากตารางราคา (71,558 แถว / 536 คู่ยี่ห้อ-รุ่น)
2. **พนักงานแก้ราคาทับได้ทุกบรรทัด** ราคาที่แก้ผูกกับใบเสนอราคานั้น ไม่ย้อนไปแก้ตารางราคา
3. **รุ่นรถไม่มีในตาราง → เพิ่มได้ทันทีจากหน้าเดียวกัน ไม่ต้องออกไปหน้าตั้งค่า**
   เพิ่มแล้วเข้าตารางราคาของสาขานั้นเลย (ตารางราคาแยกต่อสาขา)
4. ต้อง index ให้ค้นหา `(shop_id, brand, model)` เร็วพอ — 71,558 แถวต่อสาขา
5. บรรทัดแยกประเภท: `อะไหล่` / `ค่าแรง`

### อนุมัติทีละบรรทัด
ลูกค้าอนุมัติบางบรรทัด เลื่อนบางบรรทัด ปฏิเสธบางบรรทัด — **ไม่ใช่อนุมัติทั้งใบ**
บรรทัดที่อนุมัติ → ไหลเข้าใบสั่งงานของช่าง
บรรทัดที่ปฏิเสธ → ยังอยู่บนเอกสารพร้อมเหตุผล

## 6. เกณฑ์ผ่าน

1. ออกใบเสนอราคา → อนุมัติ 2 จาก 4 บรรทัด → ใบสั่งงานมี 2 บรรทัด ปฏิเสธ 2 บรรทัดยังเห็นพร้อมเหตุผล
2. ปิดบิลด้วยยอดไม่ครบ → **ออกใบเสร็จไม่ได้** พร้อมข้อความบอกส่วนต่าง
3. รับมัดจำ → ปิดบิลโดย**ไม่**เลือกมัดจำ → มัดจำยังค้างอยู่ ไม่ถูกหักเอง
4. มัดจำก้อนเดียวแบ่งใช้ 2 งาน → ยอดคงเหลือถูก และใช้เกินไม่ได้
5. เปลี่ยน status มัดจำโดยไม่กรอกเหตุผล → ไม่ผ่าน
6. เอกสารที่มีเลขที่แล้วแก้ไม่ได้ ทุกช่องทาง รวมถึงยิง API ตรง
7. รุ่นรถที่ไม่มีในตาราง → เพิ่มจากหน้าใบเสนอราคาได้ แล้วราคาขึ้นทันทีโดยไม่ต้องรีโหลด
8. พิมพ์ A4 สองชุด ฟอนต์ไทยไม่แตก ตัดหน้าถูก
9. รายงาน "เงินเข้า" กับ "ยอดขาย" ให้ตัวเลขต่างกันได้ และต่างกันถูกต้อง
10. ทุก query ผ่าน `withShop` — grep หา `unscoped` ต้องไม่เจอ
11. **ตรวจด้วยตาที่ 390px**

ตาม CLAUDE.md §14: คนเขียนห้ามรีวิวเอง
