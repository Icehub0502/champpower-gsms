## P3.2 — ใบสั่งงาน + ใบเสร็จ + ปิดบิล + สรุปยอดรายวัน + พิมพ์ A4

> **ตัดสินแล้ว 15 ต.ค. (`DECISION-2026-10-15.md` §2) — ประวัติการพิมพ์:** ทุกครั้งที่พิมพ์ ท้ายกระดาษต้องมี "พิมพ์ครั้งที่ N · วันที่ เวลา · โดย ชื่อพนักงาน" · เก็บประวัติการพิมพ์ทุกครั้ง (ใคร เมื่อไหร่ สถานะเอกสารตอนนั้น) · พิมพ์ใบที่เคยถอยการยืนยันหลังพิมพ์ → เตือน "ใบนี้เคยพิมพ์ไปแล้ว N ครั้ง เนื้อหาเปลี่ยนหลังจากนั้น — เก็บใบเก่าคืนจากลูกค้า"
>
> **ก่อนเริ่ม P3.2 ส่งคำถามบัญชี 4 ข้อให้ Ice ตอบรวดเดียว** (thai-tax 15 ต.ค.): ฐาน VAT เมื่อมีส่วนลดท้ายบิลบนบิลที่มีทั้งของและค่าแรง · VAT คิดหลังหักส่วนลดหรือไม่ (add_7 / include_7) · ใบกำกับแสดงส่วนลดท้ายบิลได้ไหม · กฎเศษสตางค์ตอนกระจายส่วนลด — ใบเสร็จต้องอ่าน `approved_total` ไม่ใช่ `grand_total`

> **ข้อสังเกตจาก WO-006 (7 ต.ค.):** `catalog_items` (0020) ยังไม่เชื่อมกับ `skus` (0006) — ต้องมี migration ใหม่เพิ่ม `catalog_items.sku_id` เป็น FK แบบผูกสาขา (composite `shop_id`) ถ้า P3.2 ต้องแตะ `catalog_items` อยู่แล้ว ให้ทำไปพร้อมกัน (ผ่าน migration-safety ตามปกติ) ไม่ต้องรอ WO-006
>
> **ตัดสินไว้แล้ว ไม่ต้องถกใหม่ (`DECISION-2026-10-07.md`):** ส่วนลดตอนออกใบเสร็จ **≤ 40% ของยอดรวม advisor ทำได้ · > 40% ต้อง manager ขึ้นไป + บังคับเหตุผล** · การพิมพ์ A4 คือตัวควบคุมแทนลายเซ็นบนจอ (ใบเสนอราคาที่มีลายเซ็นบนจอมีแค่ 1 จาก 482) — ระหว่างยังไม่มี P3.2 ให้พนักงานใช้วิธีพิมพ์เดิมไปก่อน

> **สลับลำดับกับมัดจำ (Ice ตัดสิน 6 ต.ค. — `docs/WORK-ORDERS/DECISION-2026-10-06.md` §4):** ใบเสร็จ+พิมพ์ใช้กับ 100% ของงานและไม่มีทางสำรอง มัดจำ ~5% และทำด้วยมือได้ · ช่วงแรกใบเสร็จยังไม่มีทางหักมัดจำ จะเพิ่มใน P3.3
> ใบสั่งงานใน P3.1 เป็น endpoint อ่านอย่างเดียว · ไม่มีใบ → 409 `quotation_missing` · ยังไม่ยืนยัน → 409 `quotation_not_confirmed` · ปฏิเสธทุกบรรทัด → 200 รายการว่าง

# ⬜ Phase 5 — เปิดใช้จริง

## P5.1 — นำเข้าข้อมูลรอบจริง (ทำก่อน go-live ~1 สัปดาห์)

```
ถึงเวลานำเข้าข้อมูลรอบจริงแล้ว ตาม docs/WORK-ORDERS/WO-004-master-data-import.md

Ice จะถ่าย dump ใหม่จากเซิร์ฟเวอร์มาไว้ที่ _import/
ให้รันสคริปต์นำเข้าบนฐานที่มีข้อมูลรอบทดสอบอยู่แล้ว เพื่อพิสูจน์ว่า update ไม่ใช่สร้างซ้ำ

หลังรันต้องรายงาน:
- จำนวนแถวแต่ละตาราง เทียบกับรอบทดสอบ
- รายการใน _import/review-duplicates.csv มีกี่กลุ่ม
- ยืนยันว่าลูกค้าที่ใช้เบอร์ 0999999999 ยังแยกกันอยู่ ไม่ถูกยุบ
```

## P5.2 — ตรวจก่อนเปิดใช้จริง

```
ตรวจความพร้อมก่อนเปิดใช้จริง ไล่ทุกข้อแล้วรายงานผ่าน/ไม่ผ่านทีละข้อ

1. ล็อกอินด้วยบัญชีจริงของพนักงานได้ทุกคน สิทธิ์ถูกต้อง
2. เปิดงานใหม่ → เสนอราคา → อนุมัติ → ซ่อม → ออกใบเสร็จ → ปิดบิล ครบวงจรบนข้อมูลจริง
3. พิมพ์เอกสารจริงออกเครื่องพิมพ์ที่อู่ ไม่ใช่ PDF บนจอ
4. ทดสอบบน iPad และมือถือเครื่องจริงของพนักงาน ไม่ใช่ย่อหน้าต่างเบราว์เซอร์
5. เลขที่เอกสารไม่ชนกับของระบบเก่า
6. สำรองฐานข้อมูลอัตโนมัติทำงานแล้ว และลอง restore ดูจริงหนึ่งครั้ง
7. มีทางถอยกลับไปใช้ระบบเก่าได้ถ้าวันแรกพัง
```
